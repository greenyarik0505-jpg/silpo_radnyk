# 🏛 Архітектурний опис проєкту «Сільпо Помічник»

## 1. Загальні принципи

Додаток розроблено за принципами **Clean Architecture** та **MVVM (Model-View-ViewModel)**. Основними цілями архітектури є:
- **Незалежність від фреймворків**: Доменний шар не залежить від деталей реалізації UI чи зовнішніх бібліотек.
- **Тестованість**: Усі бізнес-правила, калькуляції цін, знижок та виклики протоколу MCP покриваються модульними тестами без необхідності підняття UI або мережі.
- **Підтримка змін**: Легке додавання нових інструментів MCP або заміна бекенд-ендпоінтів без впливу на користувацький інтерфейс.

## 2. Шари архітектури

```
+--------------------------------------------------------+
|                   Presentation Layer                   |
|  - Screens (ChatScreen, PromoScreen, CartScreen, ...)  |
|  - ViewModels (ChangeNotifier)                         |
|  - Widgets (ProductCard, CartItemTile, PromoCard, ...) |
+--------------------------------------------------------+
                           |
                           v
+--------------------------------------------------------+
|                      Domain Layer                      |
|  - Entities (Product, Recipe, CartItem, Promo, ...)    |
|  - Business Rules & Calculations                       |
+--------------------------------------------------------+
                           ^
                           |
+--------------------------------------------------------+
|                       Data Layer                       |
|  - Repositories (SilpoRepository)                      |
|  - DataSources (SilpoMockDataSource, RemoteDataSource) |
+--------------------------------------------------------+
                           |
                           v
+--------------------------------------------------------+
|                       Core Layer                       |
|  - MCP Protocol & Client (JSON-RPC 2.0 / SSE)          |
|  - Network & Result (ApiResult)                        |
|  - Theme & Constants (AppColors, AppStrings)           |
+--------------------------------------------------------+
```

### Core Layer
- `mcp_protocol.dart`: Реалізація специфікації Model Context Protocol JSON-RPC 2.0 (повідомлення, помилки, інструменти, контент).
- `mcp_client.dart`: Клієнт для зв'язку з `https://mcp.silpo.ua/mcp`. Підтримує чергу діагностичних повідомлень та розумний локальний режим для розробки.
- `silpo_mcp_tools.dart`: Оголошення 39 інструментів з детальними JSON-схемами параметрів.

### Domain Layer
- Чисті, незмінні Dart-класи (`Product`, `Recipe`, `CartItem`, `FiscalReceipt`, `SilpoStore`, `PromoItem`).
- Розрахунок знижок, економії, вартості рецептів та балів лояльності «Власний Рахунок».

### Data Layer
- `SilpoRepository`: Єдина точка доступу до даних. Координує джерела даних, виконує кешування, агрегує аналітику чеків та передає виклики до MCP.

### Presentation Layer
- Реалізовано за патерном MVVM.
- Кожен екран має свій `ViewModel`, який успадковує `ChangeNotifier` та сповіщає віджети через `ListenableBuilder`.
- Повний набір адаптивних віджетів для мобільних та десктопних екранів.

## 3. Модель потоку даних для AI Recipe-to-Cart

1. Користувач вводить текст рецепта в `ChatScreen`.
2. `ChatViewModel` викликає метод `parseRecipe()` репозиторію.
3. Репозиторій логує виклик `tools/call` через `McpClient` для інструменту `silpo_parse_recipe`.
4. Отриманий об'єкт `Recipe` містить список інгредієнтів, зіставлених з конкретними товарами `Product`.
5. Повідомлення відображає інтерактивну картку рецепта з кнопкою «Додати все до кошика».
6. При натисканні `CartViewModel.addRecipeIngredients()` наповнює кошик, оновлює бейдж та перераховує персональну економію.
