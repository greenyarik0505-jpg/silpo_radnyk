# Керівництво для розробників (Contributing to Сільпо Помічник)

Дякуємо за інтерес до покращення **Сільпо Помічник**! Будь-який внесок — виправлення помилок, нові інструменти MCP, дизайн або покращення продуктивності — дуже вітається.

---

## 📋 Процес розробки

1. **Форкніть репозиторій** та створіть гілку для своєї функціональності від `main`:
   ```bash
   git checkout -b feature/awesome-new-feature
   ```
2. **Встановіть залежності**:
   ```bash
   flutter pub get
   ```
3. **Дотримуйтесь стандартів коду**:
   - Переконайтеся, що код відповідає правилам `flutter_lints` та `analysis_options.yaml`.
   - Запустіть автоматичне форматування:
     ```bash
     dart format .
     ```
   - Запустіть аналіз коду:
     ```bash
     flutter analyze
     ```
4. **Пишіть тести**:
   - Для кожної нової функціональності обов'язково додавайте відповідні юніт-тести у каталог `test/`.
   - Переконайтеся, що всі тести проходять:
     ```bash
     flutter test
     ```
5. **Створюйте зрозумілі коміти** за конвенцією Conventional Commits:
   - `feat: додати фільтрацію товарів за веганським маркуванням`
   - `fix: виправити розрахунок відсотка знижки для акцій Цінотижиків`
   - `docs: оновити документацію викликів Silpo MCP`
6. **Створіть Pull Request** з детальним описом змін та скріншотами (якщо змінювався інтерфейс).

---

## 🎨 Стиль коду та архітектура

- **Separation of Concerns**: Не змішуйте UI-код з логікою отримання даних або викликами MCP.
- **Чисті сутності**: Доменні моделі в `lib/domain/entities/` повинні бути незмінними (`immutable`).
- **ViewModels**: Використовуйте `ChangeNotifier` з методами оновлення стану та підпискою через `ListenableBuilder`.
- **Локалізація**: Усі тексти та назви виносьте до `AppStrings`.
